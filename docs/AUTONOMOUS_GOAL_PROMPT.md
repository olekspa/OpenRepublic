# OpenRepublic sustained-goal prompt

Use this as the objective text for a Codex `/goal` while the OpenRepublic repository is open. A goal prompt can keep the task active across supported continuations, but cannot keep a desktop session, machine, or automation running after an external service/session limit; use a scheduled heartbeat if unattended wakeups are required.

```text
/goal Continue developing OpenRepublic in the current repository toward a genuinely playable, independent WRSR-compatible alpha. Keep this goal active until the acceptance criteria below are demonstrated. Do not mark it complete after research, setup, documentation, a synthetic rendering, a compile, or a partial prototype.

Work autonomously through ordinary reversible engineering decisions. Do not ask preference or permission questions for local inspection, documentation, code changes, builds, tests, or bounded read-only checks. If one path is blocked, record the exact evidence and uncertainty, then continue an independent useful path. Never claim to be running overnight or in the background unless a scheduler actually resumed the work. At every execution boundary, leave the goal active, save a concise checkpoint with exact repository state, verified tests, open blocker, and next command/action, and resume from that checkpoint on the next continuation without repeating completed work.

First inspect git status, current goal, project docs, installed tools, and the local Rival Republics research before changing anything. Preserve Rival Republics and the Steam WRSR installation as read-only sources. Keep VERIFIED, INFERRED, and UNKNOWN distinct. Do not copy unlicensed code, game assets, saves, decompiler output, proprietary hashes, or private research artifacts into the public repository. Preserve unrelated working-tree changes and commit only reviewed OpenRepublic-owned paths. Publish reviewed OpenRepublic changes through the configured GitHub repository when they are ready.

Prefer an independently owned architecture: Wicked Engine presentation behind replaceable adapters, authoritative deterministic fixed-step C++ simulation, versioned OpenRepublic save/load, and narrowly scoped reloadable Lua rules/data. Use REA/Ghidra and existing community research for questions they can actually answer; revalidate version-sensitive findings. Measure simulation, renderer, loading, and memory separately. Build in both Windows-client and headless configurations. Keep public project docs and the private research ledger current.

The playable-slice acceptance is complete only when: (1) a clean documented checkout reproduces builds and tests; (2) an OpenRepublic client renders a bounded local world and supports camera movement, selection, and construction; (3) one representative local content path has verified geometry/material handling and one bounded terrain region has independently checked coordinate/orientation/elevation against landmarks, or a reproducible blocker is documented and the first playable slice uses an open/synthetic map; (4) the C++ simulation runs a complete production → storage → road/truck → cargo delivery loop with deterministic, validated independent save/load; (5) Lua rules/data reload safely and are exercised in-app; and (6) a fresh reviewer can run the first slice and understand its known gaps. Do not claim full WRSR parity, broad save compatibility, or legal clearance without separate evidence.

After each meaningful slice, run the relevant build/runtime checks, record exact receipts and limitations, review the diff and ignored/private files, update docs, then commit/push only those reviewed project files. Continue to the next independent milestone instead of stopping for a status-only response. If context, execution time, or service limits force a stop, do not mark the goal complete or blocked prematurely; leave the goal active and produce the exact restart checkpoint.
```
