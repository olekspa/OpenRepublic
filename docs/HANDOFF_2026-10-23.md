## What exists now

### Economy, API, and host

- **VERIFIED (OpenRepublic source/build/test scope):** the C++ economy remains authoritative. The typed `EconomyApi` and protocol-v0 JSONL host provide construction, roads, utilities, hauling, advice, summaries, paging, and persistence interfaces. The app can own the region economy; `--economy-url` remains the separate-host route. See `ECONOMY_API.md` and `ECONOMY_AGENT_PLAYBOOK.md`. The 23 October log records the resumed client suite at 68/68 (~03:10), economy summary at 71/71 (~15:40), and final trade/controller integration at 76/76 (~22:40).
- **VERIFIED (measured workloads only):** cached road adjacency/traversal, ordered ID lookup, reduced API snapshots, and paged world queries improved measured synthetic workloads while recorded hashes matched. On a 40,000-building workload, 1,500-haul tick time changed from about 5.9 ms to 0.52 ms; 5,000-haul time changed from about 6.4 ms to 0.19 ms after the worker-startup fix. A 32-building page was also measured on that synthetic world. The local imported-region benchmark and limits are documented in [ECONOMY_PERFORMANCE.md](ECONOMY_PERFORMANCE.md); these are workload-specific measurements, not general performance guarantees.
- **OBSERVED:** the real-region imported workload was exercised as a bounded OpenRepublic import/API benchmark with a read-only query hash guard. The log and performance guide describe importer results, not original-game simulation semantics.
- **UNKNOWN:** broad WRSR economy parity, imported production state, native utility topology/port semantics, general catalog coverage, and large combined building/road workloads. Keep electrical and other original-content connection semantics bounded by the evidence ledger.

### Scenarios and AI controllers

- **VERIFIED (OpenRepublic synthetic scope):** `data/scenarios/` contains inventory, road, power/utility, and trade fixtures; `tools/scenario_score.py` runs deterministic scoring against a fresh host. The scorer supports stored non-raw inventory and utility multi-objective breakdowns. The baseline table and metric boundaries are in [SCENARIOS.md](SCENARIOS.md). The 23 October log records scenario integration and CTest 72/72 (~16:40), utility follow-ups through 73/73 (~19:50), and trade integration at 76/76 (~22:40).
- **VERIFIED (controller/tooling scope):** `tools/republic_autopilot.py` is the rule-based baseline. `tools/llm_republic.py` supports Codex, OpenAI-compatible, Claude, and scripted backends, validates a bounded action schema, logs JSONL transcripts, and can replay validated actions against a fresh matching host. The tournament harness compares controllers on fresh worlds; scenario mode uses the scripted backend for local test coverage. See [LLM_REPUBLIC.md](LLM_REPUBLIC.md).
- **OBSERVED (one region, metric, and small sample):** two improved N22-region LLM runs scored approximately 772.0 and 782.3 at tick 4012 against the rule-based autopilot's 730.4 at tick 4017. Each improved run had rejected actions. This two-run result is preliminary and model-dependent; tick counts differ.
- **UNKNOWN:** repeatable general LLM advantage, performance on other worlds or metrics, and any connection to WRSR controller behavior. Region-specific transcripts or inputs can contain private map details and belong outside Git.

The parallel terrain work did not produce a meaningful startup improvement.

N22 top-down and hero captures were checked. Frame-time benefit is **UNKNOWN**. Road width, class, lane semantics, and decoded point meaning remain **UNKNOWN** or **INFERRED**; renderer widths are presentation policy. The optional private DLSS Frame Generation path submits depth, motion vectors, HUD-less colour and UI colour/alpha tags; Streamline options and Reflex calls returned success in the logged probe.

DLSS patches are not integrated into the default/public build path. Do not treat tag submission or a successful feature call as visual, temporal, latency, or performance acceptance. ### Scene control and Lua

- **VERIFIED (OpenRepublic API and app scope):** `OpenRepublicSceneControl` is an engine-independent C++17 presentation API for look and camera changes. The app can serve it over a local named pipe with `--scene-pipe-name`; requests apply at frame boundaries. The 22 October guide records a live scene change check and its trusted-local limitations.
- **VERIFIED (sandboxed library tests); OBSERVED (one live example):** bounded Lua scene scripts expose `or.look`, `or.camera`, `or.time`, `or.log`, and `on_frame(dt)` for presentation control. The app accepts `--scene-script <file.lua>`; the `day_cycle` example loaded and ran in the modern view. The 23 October log records headless CTest 68/68 for the Lua increment (~05:30).
- **UNKNOWN:** broad script robustness, arbitrary mod support, simulation control through Lua, and any WRSR scripting compatibility. Lua scene control is not evidence that Lua rules or scene values match the original game.

## Build, test, and run

Use a Windows CMake environment with the required compiler/toolchain and the repository's pinned dependencies. The documented handoff build is headless; do not infer a client or graphics result from it.

```powershell
cmake -S . -B build/headless -DOPENREPUBLIC_BUILD_CLIENT=OFF
cmake --build build/headless --config Release -- /m
ctest --test-dir build/headless -C Release
```

For deterministic synthetic scenario scoring after the build, for example:

```powershell
python tools/scenario_score.py --host build/headless/src/economy_host/Release/OpenRepublicEconomyHost.exe --scenario data/scenarios/full_chain.json --ticks 1000
```

To run a controller on a synthetic scenario, use `tools/llm_republic.py` or `tools/republic_tournament.py` with `--scenario <id|path>`; scripted backend runs avoid a live model dependency. The host executable's actual output path can vary by generator/configuration. The LLM and trade guides document region/controller invocations. A graphical showcase requires a separate client build and appropriate content inputs. The documented hero invocation is `OpenRepublic.exe --map-building 61 --map-region --map-radius 250 --map-lod 0 --modern --showcase-camera -120 16 0.9 --showcase-sun 17 45`; add `--scene-script data/scripts/day_cycle.lua` to exercise the checked example. Local WRSR content, if used, must remain read-only and outside Git. The 23 October log's build/test counts are historical verification receipts, not a substitute for rebuilding the current checkout.
