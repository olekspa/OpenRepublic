# WRSR map terrain data: materials, vegetation, and water

**Evidence scope:** static package/content inspection and existing build-scoped loader research for local WRSR build `23935965`. The game was not launched for this report. “VERIFIED” means the stated file/header/layout fact was directly checked in the inspected read-only package; “OBSERVED” records names/configuration or loader references without assigning a complete semantic meaning; “INFERRED” is a testable interpretation; “UNKNOWN” marks unresolved semantics. Findings are sample- and build-scoped unless stated otherwise.

## Existing coordinate baseline

- **VERIFIED (one map, see the terrain entry in [the reverse-engineering ledger](REVERSE_ENGINEERING_LEDGER.md)):** `script.ini` carries `$WORLDSIZE`, `$WORLDPOSITION`, `$HEIGHTSCALE`, and `$HEIGHTMAPSIZE`; a 2048×2048 legacy R32F `heightmap.dds` is paired with that metadata. For that already-recorded map, the candidate mapping `height = raw × HEIGHTSCALE + WORLDPOSITION.y`, X/Z extent of −10,000…+10,000 m, and columns=X / rows=Z was validated against 28 building origins. This was one map, not proof for every map.
- **UNKNOWN:** whether terrain masks, grass, tree records, or water use precisely the same raster orientation, sample-center convention, or extent as the heightmap. Do not silently align by matching dimensions.
- **OBSERVED:** an inspected package’s metadata declares a 20,000×20,000 m world, a 2048×2048 heightmap, and a separate grass-map size of 1024×1024. In that package the `grassmap.dds` header is only 32×32. This mismatch is unresolved; it could reflect a low-resolution auxiliary/placeholder, a separate role, or another format convention.

## Loader and evidence boundary

- **VERIFIED (existing ledger, build `23935965`):** OpenRepublic’s read-only heightmap reader supports the inspected legacy R32F DDS profile, and the existing map transform has one-map building-height cross-check evidence. This is height data only.
- **OBSERVED (build `23935965`, static material/config review):** terrain material MTL files reference named texture inputs; script metadata supplies world/height and terrain/grass generation parameters. This supports the existence of a configurable material and grass path, not the interpretation of mask channels or runtime behavior for every layer. It is not a traced proof of the terrain shader's channel sampler bindings.
- **UNKNOWN:** no completed loader trace in this evidence set establishes the exact sampler bindings/channel swizzles for `mask.dds`, map-to-world transform for all auxiliary maps, serialized `trees.bin` record schema, or water surface construction/sea-level lookup. Static file names and a successful header parse cannot fill those gaps.

## Terrain shader evidence update (build 23935965)

- **VERIFIED (compiled shader reflection/string inventory):** the current terrain shader artifact exposes four layer tile-size values, per-layer detail tile-size values, a global detail tile size, detail alpha start/end/power values, a grass-mask name, a seasonal transition coefficient, and texture/sampler stage names. This confirms interface names only; it does not establish which material entry supplies them or how they are evaluated.
- **OBSERVED (material/config inventory):** `material.mtl` and fall/winter variants declare multiple ordered texture inputs. The map script declares `$TILESIZE1…4`, `$MASKTILESIZE1…4`, `$DETAILTILESIZE`, and `$DETAILALPHASTART`. The corresponding names/ordinals suggest related configuration, but exact constant assignment and coordinate formula remain **UNKNOWN**.
- **UNKNOWN:** no checked evidence establishes which numbered MTL texture binds each shader sampler, whether numbered textures are blended by mask RGBA or another field, the blend function, mask-detail channel use, height/slope thresholds, detail alpha fade curve, normal-map decode/blending, or seasonal texture selection behavior. Do not derive these rules from parameter names or texture filenames. The inspected INIX artifacts are compiled containers rather than readable HLSL, and available loader traces do not connect their sampler-stage indices to MTL entries.
- **INFERRED OpenRepublic preview policy:** `ComputeTerrainBlend` returns equal weights for four configured tile layers without interpreting mask, height, or slope. These configured layers are not proven to correspond one-to-one with MTL sampler slots. It computes reciprocal tile-size frequencies for UVs; this mapping is inferred and is not a claim about WRSR. Invalid tile sizes use a finite documented fallback. The helper is not a reconstructed WRSR shader.
- Private evidence and exact source identities remain in local research storage; proprietary shader text and binary assets are not included here.

## Minimal decoder plan

1. **Ground texture first — UNKNOWN semantics:** add a bounded DDS reader for the observed RGBA8 mask and BC1 auxiliary layers, preserving raw channels. Produce diagnostic channel views; use paired terrain material declarations to inventory candidate texture slots. Promote channel labels only after a loader/shader trace or controlled in-game overlay confirms them. Keep sample orientation/extent explicit rather than borrowing the height transform.
2. **Grass map — UNKNOWN stored meaning:** parse script parameters and report the on-disk grassmap dimensions separately from the declared size. First correlate layer/channel values with known map regions and grass inputs. Do not generate grass from the configured `GRASSNUMPERNODE` until its units and invocation conditions are established.
3. **Tree placement — UNKNOWN schema:** reverse the `trees.bin` reader/writer in the build-matched executable; define bounded record count, type identifiers, transforms, and payload checks before decoding. Resolve type IDs against shared tree definitions and model/texture families. Preserve exact transforms and season variants; avoid inventing random forest placement.
4. **Water — UNKNOWN extent and level:** trace water structure/heightmap consumers and identify whether per-map water geometry or shared river assets are involved. Compare candidate surface heights against controlled terrain-height and visual shoreline references before encoding sea-level behavior. Keep the existing heightmap separate from water until verified.
5. **Other overlays — UNKNOWN:** inventory and decode emissive/far/farm layers independently, with size/channel validation and a loader consumer for each before rendering them.

All readers should be version-scoped, reject unsupported DDS encodings, retain raw channel data, and leave unknowns visible in output. No proprietary assets or save payloads belong in OpenRepublic source or releases.

## Recommended next visual steps

1. **Ground texture mask and tile binding:** largest continuous visual gain; decode raw mask, establish channel-to-material mapping, then render a small matched region.
2. **Explicit tree placement:** likely high visual impact in a city-region view; first recover and validate `trees.bin` records and shared type lookup.
3. **Water extents and level:** implement only after identifying the map’s actual water representation and transform.
4. **Grass generation and minor overlays:** add after resolving the grassmap size discrepancy and emissive/far/farm semantics.
