# Streamline integration plan for Wicked Engine

**Status (22 October 2026): the opt-in path compiles and evaluates DLSS Quality and Performance in private windowed OpenRepublic runs on the RTX 5070 Ti.** Patch 0007 adds an environment-selected Performance preset while keeping Quality as the default. At 3840×2132 with RTAO, ray-traced reflections/diffuse and bloom, app FPS was 60.11 native, 77.24 FSR2 Quality, 65.64 DLSS Quality, and 79.19 DLSS Performance; sampled GPU utilization stayed near saturation. In this scene Performance was about 31.8% faster than native and 20.6% faster than Quality. Static RGB comparison against the native image favored FSR2 Quality (23.81 dB / 0.820 whole-frame PSNR/SSIM), then DLSS Quality (22.39 / 0.739), then DLSS Performance (21.52 / 0.684); the detail crop showed the same order. Visual crop inspection found DLSS Quality softer than native/FSR2 and Performance had the largest fine-detail loss. These are one-scene app frame-rate and single-capture image results, not GPU-only frame times or temporal quality proof. Frame Generation remains unimplemented.

## Patch contents

`0001-streamline-sdk-build-boundary.patch` adds the OFF-by-default `OPENREPUBLIC_STREAMLINE_DIR` option plus `OPENREPUBLIC_STREAMLINE_SDK_ROOT`; it consumes SDK headers in place and copies no NVIDIA files. `0002-streamline-dlss-runtime.patch` is layered after 0001. `0003-streamline-deferred-resize.patch` is layered after 0002 and fixes lazy sizing/resource allocation. `0004-dlss-quality-preset.patch` selects the SDK enum value `eMaxQuality` for OpenRepublic's DLSS Quality mode. `0005-preserve-fsr2-targets.patch` keeps the shared FSR output targets alive while FSR2 is selected and DLSS is off. `0006-exact-dlss-quality-scale.patch` uses the limiting scale ratio because Wicked's internal target rounds dimensions upward; this lets the exact-size runtime guard dispatch DLSS at the largest tested output. `0007-dlss-performance-preset.patch` adds `OPENREPUBLIC_DLSS_PRESET=performance` for `eMaxPerformance`; unset or any other value keeps `eMaxQuality`. All remain inert in default builds.

Patch 0002 loads `sl.interposer.dll` by an absolute executable-directory path before Wicked loads DXGI/D3D12, calls `slInit` with `kFeatureDLSS`, uses interposer factory/device creation exports when present, calls `slSetD3DDevice`, and shuts down after `WaitForGPU`. It exposes native D3D12 handles and converts the tracked engine texture layout to `D3D12_RESOURCE_STATES`. The initial patch selects Balanced; patch 0004 changes both the optimal-settings query and per-frame options to `eMaxQuality`. `RenderPath3D::setDLSSEnabled(true)` requests optimal dimensions, updates render scale, allocates display-size output resources, and schedules DLSS at the existing FSR2 postprocess location. The per-frame path supplies a token, camera constants, depth/motion/color input/color output tags and `slEvaluateFeature(kFeatureDLSS)`; it uses auto exposure because no validated Streamline exposure texture mapping was established.

OpenRepublic's `runtime::Upscaler::Dlss` was connected to the render-path flag in the private app copy. The initial early settings call can occur at `0×0`; patch 0003 keeps that request pending and initializes after the first nonzero physical size. A later resize is detected by comparing DLSS output resource dimensions with the current physical dimensions and calling the same setup path. A resize event was not exercised in this run.

## Concrete integration sequence

1. **Acquire and pin SDK files outside Git.** Use the public [NVIDIA-RTX/Streamline repository](https://github.com/NVIDIA-RTX/Streamline) for source/guides and its [releases page](https://github.com/NVIDIA-RTX/Streamline/releases) for runtime binaries. The inspected source/tag is Streamline `v2.14.16`, commit `625db07d4bca5abc67d781c42af7e7fb0761f1b6`. **VERIFIED:** downloaded the public v2.14.16 release ZIP privately (SHA-256 `32041e51db0cab709a271b72a352281b690c2abbd669a827809401a5dd23956b`); the four runtime DLLs used were Authenticode-valid and signed by NVIDIA. No SDK binaries were added to Git.
2. **Initialize before DXGI/D3D12.** In an opt-in Windows build, the patch loads `sl.interposer.dll` from the executable directory and calls `slInit` before Wicked loads DXGI/D3D12. It requests D3D12, `kFeatureDLSS`, plugin directories (`plugins` then executable directory) and frame-based resource tagging. It does not call from `DllMain`. Missing DLLs or initialization failure leave the existing renderer path available.
3. **Bind device and check feature support.** After Wicked creates its device, the patch calls `slSetD3DDevice`. The per-frame DLSS function calls `slIsFeatureSupported` with the adapter LUID and returns to the non-DLSS path on failure. The patch attempts to use the interposer's `CreateDXGIFactory2` and `D3D12CreateDevice` exports; successful proxy/present behavior has not been verified.
4. **Submit a per-view frame.** The implementation obtains one `FrameToken` for a DLSS dispatch, sets camera matrices/jitter constants, tags a viewport's depth, velocity, HDR input/output color, then calls `slEvaluateFeature(kFeatureDLSS)` on Wicked's command list. It removes the projection jitter before providing matrices. Reversed depth is source-verified in Wicked's camera code. Motion-vector scale and jitter interpretation remain inferred from the FSR2 integration and need runtime validation.
5. **Use DLSS at the HDR postprocess point.** The patch stack selects Quality mode (`eMaxQuality`) by default, obtains optimal dimensions with `slDLSSGetOptimalSettings`, scales the render path, and creates display-sized output resources. Patch 0003 defers this sequence at zero size and retries on size/resource mismatch; patch 0006 aligns the input allocation to the queried optimal size when Wicked rounds its internal dimensions up. Patch 0007 selects Performance (`eMaxPerformance`) when the process environment contains `OPENREPUBLIC_DLSS_PRESET=performance`; the same mode is used for sizing and per-frame options. It evaluates in the existing FSR2 slot, before tone mapping. It enables `useAutoExposure`; it does not tag an exposure resource because Wicked's scalar exposure and luminance texture have not been shown to meet the Streamline texture contract. Follow-up 8 logged Quality at 2560×1421 input and Performance at 1920×1066 input, both with 3840×2132 output and successful evaluation. The initial resize was observed; repeated arbitrary resize cycles and full temporal image correctness remain unverified.
6. **Fail safely and close the module.** API failures return to the ordinary temporal/postprocess path; `slShutdown` is called after the graphics queue is drained. The patch does not yet validate NVIDIA DLL signatures, explicitly report all failure reasons to OpenRepublic, or handle device loss beyond normal fallback. Interposer present behavior and plugin resource lifetime need runtime testing.
7. **Keep Frame Generation out of scope.** DLSS-G, Reflex markers and HUD/UI composition are not implemented. The patch requests only DLSS SR.

## OpenRepublic setting mapping

`src/runtime/graphics_settings.*` already parses `runtime::Upscaler::Dlss` and reports it unavailable. Map that neutral setting to the Streamline backend only when the Windows/D3D12 build option is ON and post-device support validation succeeds:

| OpenRepublic choice | Streamline mapping | Current status |
| --- | --- | --- |
| `Upscaler::None` | Do not evaluate a Streamline feature | Existing path |
| `Upscaler::Fsr2Quality/Balanced/Performance/UltraPerformance` | Preserve existing FSR2 modes | Existing engine path |
| `Upscaler::Dlss` | Selects `RenderPath3D::setDLSSEnabled(true)`; Quality is default; `OPENREPUBLIC_DLSS_PRESET=performance` opts into `eMaxPerformance` | **OBSERVED:** Quality evaluated with 2560×1421 input and Performance with 1920×1066 input at 3840×2132 output; initial zero-size request remains pending until setup can proceed |
| `GraphicsSettings::sharpen` | Map only if Streamline DLSS options offer the corresponding control in the selected SDK version, otherwise keep OpenRepublic's post-sharpen pass | Requires version-specific review |
| Frame generation | Separate future setting; do not overload `Upscaler::Dlss` | Not implemented; lacks HUD-less/UI buffers and present contract |

The UI/runtime must expose actual availability and reason (SDK not built, DLL missing/invalid, unsupported adapter/driver, initialization failure), never silently label FSR2 as DLSS.
